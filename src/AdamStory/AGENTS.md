# Alien visitor story project

- Add Adam's story as a separate mod; preserve vanilla customers, the dog mod, and user saves. Never stop an existing game process without task-specific authorization.
- Story state belongs to each game run; preserve it on reload and use stable namespaced IDs. Never write test state into the user's existing runs.
- The first four refusals are explicit, distinct visits, not elapsed days or unavailable inventory. Aid accepts one food OR one water. Adam's portrait remains bound to Adam alone and never falls back to random customer art.
- After aid Adam identifies as Adam; the story has progressive starvation, a scavenger phase, a three-day delay, repeatable requests, an electronics delivery, a self-recharging battery request, a space ending, and a stay branch with a three-day ten-iron-ore device.
- After four refusals the god appears the next day; apology opens a seven-day restitution period for food totalling 100 kcal, with redemption or a bad ending.
- Testing was completed by the user; formal release disables previews by default. If explicitly enabled, same-day previews cover the dog, four Adam health states, scavenger outfit, and god; testing uses no real resources, never advances formal story, and provides a non-destructive third-day decision.
- The first normal story encounter must not occur before in-game day 23. The user-requested preview is separate from the story-day threshold.
- Inspect local game APIs and distinguish native support, targeted patches, code-level evidence, isolated tests, and actual in-game acceptance. Use independent test saves and do not overwrite current saves.
- Do not install until the full requested scope is implemented and validated; retain prior install/rollback data and do not overwrite unrelated mods.
